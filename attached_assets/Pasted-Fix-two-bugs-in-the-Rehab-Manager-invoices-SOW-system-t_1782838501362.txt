**NEW FEATURE — Stage Payments**

Contractors are often paid in milestones (e.g., 50% on completion, 25% on inspection, 25% on final). Add a payment schedule to invoices.

**DB migration:**
Create a new model `InvoiceStage`:
```sql
CREATE TABLE "InvoiceStage" (
  id TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
  "invoiceId" TEXT NOT NULL REFERENCES "Invoice"(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  description TEXT,
  percentage DECIMAL(5,2),
  amount DECIMAL(14,2) NOT NULL,
  status TEXT NOT NULL DEFAULT 'Pending',
  "triggerEvent" TEXT,
  "dueDate" DATE,
  "paidAt" TIMESTAMPTZ,
  "order" INT NOT NULL DEFAULT 0,
  "createdAt" TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX ON "InvoiceStage"("invoiceId");
```

Add to Prisma schema:
model InvoiceStage {

id          String    @id @default(cuid())

invoiceId   String

invoice     Invoice   @relation(fields: [invoiceId], references: [id], onDelete: Cascade)

name        String

description String?

percentage  Decimal?  @db.Decimal(5,2)

amount      Decimal   @db.Decimal(14,2)

status      String    @default("Pending")

triggerEvent String?

dueDate     DateTime? @db.Date

paidAt      DateTime?

order       Int       @default(0)

createdAt   DateTime  @default(now())

}
Add `stages InvoiceStage[]` to the Invoice model.
Run migration + prisma generate.

**API updates:**
- `GET /api/rehab/[projectId]/invoices`: include `stages` in the response
- `POST /api/rehab/[projectId]/invoices`: accept optional `stages` array, create InvoiceStage rows
- `PATCH /api/rehab/[projectId]/invoices/[invoiceId]`: accept `stages`, upsert them (match by id if existing, create if new, delete removed ones)
- New route `PATCH /api/rehab/[projectId]/invoices/[invoiceId]/stages/[stageId]`: update a single stage status (Pending → Paid) and set paidAt = now()
